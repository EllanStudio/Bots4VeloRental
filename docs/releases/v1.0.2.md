# Bots4Velo Rental v1.0.2

## AuthMe compatibility

This release fixes the rental addon flow after an AuthMe update changes the
timing of the Velocity login and backend server transition.

- The addon now builds against Bots4Velo Addon API `3.0.3`, pinned to the
  released core commit `95f027b525fc0974c5019a501445996a84d76697`.
- A lease sends at most one asynchronous server-switch request while the
  authentication transition is pending. The result is observed before another
  request is scheduled.
- Successful and already-connected results continue the normal activation
  path; authentication-pending and failed results clear the in-flight guard so
  the regular backoff can retry.
- Disconnect, stop, cancellation, timeout, and refund paths clear the
  transient request state.

## Upgrade

1. Publish/install Bots4Velo core `v3.0.3`.
2. Replace the Velocity addon with `bots4velo-rental-addon-1.0.2.jar`.
3. Replace the redstone bridge with `bots4velo-rental-paper-1.0.2.jar` when it
   is part of the deployment.
4. Restart the affected Minecraft process after replacing a JAR, then verify
   one rental through AuthMe login and the `redstone` transition.

The release does not alter the on-disk lease schema. Keep `rentals.db` and
`processed-refunds.properties` during the upgrade.
